Architectural Excellence

Designed for local resource-constrained loops where low-latency and context size optimization are critical.

Sub-5ms Semantic Search

Utilizes native Model2Vec structures. Autovectorized CPU sweeps compare thousands of embeddings instantly using optimized float operations.

AST Structural Chunking

Tree-sitter boundary discovery respects formal code blocks (structs, functions). Prevents syntax splitting so LLM context windows stay accurate.

Hybrid Blending Engine

Exact matches require BM25. Conceptual queries require semantic vectors. Semble-RS fuses both via RRF and boosts function definitions natively.

Concurreny via Rayon

Exploits multi-core architectures. Paralellizes parsing, chunking, and embedding to indexing in ~1.46s (a 40% speed drop sequential).

Drop-in MCP stdio protocol

Runs as a Model Context Protocol server over stdio. Seamless, instant addition to environments like Claude Code, Cursor, or Cline.

Offline Model Cache

Static token matrices are fetched from Hugging Face on first run and cached locally via the official model2vec-rs crate. Perfect for air-gapped secure development.

Quick Start & Setup

Deploy the high-performance local server to your agent in seconds.

bash — install & config
# 1. Compile the native release binary from source
$ cargo build --release
# 2. Install the executable into your local path
$ cargo install --locked --path .
# 3. Add to Claude Code as a local MCP stdio server
$ claude mcp add semble -s user -- semble
# 4. Or query codebases directly from your CLI terminal
$ semble search "authentication flow" ./src

Frequently Asked Questions

Answers to common questions about Semble-RS capabilities and operations.

What is Semble-RS and how does it compare to the original Python library?

Semble-RS is a native Rust implementation of MinishLab's Python semble library. It compiles into a single executable binary, completely eliminating the need for a Python runtime, virtualenvs, or standard library version conflicts.

While the original Python library is highly optimized, Semble-RS achieves much lower latencies (sub-millisecond semantic retrievals vs. ~1.5ms in Python) and fully utilizes multi-core systems via parallel Rayon threads, reducing indexing times by 40%.

How does the search blend keyword matches and semantic intents?

Exact matches for variable identifiers or struct names are crucial in codebases. A pure vector semantic search often misses exact string matches. Semble-RS addresses this by constructing an in-memory BM25 lexical index alongside static token embeddings.

At search time, both retrieval paths run, and their candidate pools are combined using Reciprocal Rank Fusion (RRF) with a ranking constant of 60. Then, code-aware structural reranking boosts explicit function and structure definitions, bringing structural context directly to the top.

How do Model assets get installed? Is an internet connection required?

On the first search run, Semble-RS loads the highly optimized static embedding assets for minishlab/potion-code-16M through the official Model2Vec Rust crate, downloading them from the Hugging Face Hub into a platform-appropriate local cache.

Once these assets are cached, subsequent indexes and searches run completely offline with no network calls, which is perfect for air-gapped systems or secure development environments. If no weights are available, a reduced-quality hashing encoder takes over automatically.

Can I swap standard transformers for custom models?

Traditional transformer models (such as BERT or Sentence-Transformers) cannot be loaded dynamically because Semble-RS relies on the ultra-lightweight Model2Vec architecture for static, fast CPU projections.

However, you can point Semble-RS to any pre-distilled static Model2Vec model by configuring the SEMBLE_MODEL_DIR environment variable with a local model directory or a Hugging Face repo id.
